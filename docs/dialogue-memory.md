# 对话记录与持久调用额度

> 此文描述legacy `--db/--chat-db`的独立侧库方案。新六核心 `--subject-db`已用单一事务库统一主体/经历/记忆/问答/额度，见[主体运行接线](subject-runtime.md)。不自动把两份旧库合并。

## 为什么与主体库分开

主体库 schema v1 继续只保存身份、性格等快照及生命周期事件，不自动迁移。新增的对话库有独立应用 ID/schema，保存一个主体、一个可信所有者会话的对话记录与调用台账。它绑定主体 ID，不能误接到另一主体；这不是多用户/多会话隔离方案，也不防用户复制同一个 ID 的库。

对话记录表示“某次用户说了什么、模型回复了什么”，不表示这些话是真实事实，也不是性格、情绪或长期知识的自动变更。不会直接写入 `memoryIds`、beliefs、affect 或成长提案。

## 显式启用

父目录必须已存在且私有。先有主体库，再显式创建新对话库：

```bash
DB="$HOME/.local/share/shuguang-intelligence/dawn.sqlite"
CHAT="$HOME/.local/share/shuguang-intelligence/chat.sqlite"
npm start -- chat-init --db "$DB" --chat-db "$CHAT" --limit 100
npm start -- chat-budget --db "$DB" --chat-db "$CHAT"
npm start -- serve --db "$DB" --token-file "$HOME/.local/share/shuguang-intelligence/service.token" --port 7341 \
  --model-config /absolute/path/model.json --chat-db "$CHAT"
```

- `chat-init` 仅创建新文件，不覆盖、重置或自动续期；额度 1–10000 次，创建后固定。
- `chat-budget` 只返回调用计数，不输出对话正文。
- 启用模型的 serve 必须同时提供 `--model-config` 与 `--chat-db`。不配模型的控制服务不需要对话库。
- `serve` 只打开已有对话库；旧的仅 `--model-config` 命令现在会失败，需要显式初始化台账。这是刻意的失败关闭，避免悄悄回退为无持久预算模式。
- `config.maxCalls` 的实例上限仍生效，和对话库额度取实际先触发者。重启可重置实例限额，但不会重置同一对话库的额度。
- 本轮不会执行这些正式初始化命令，也不会自动把旧模型测试转换为主体经历。

## 一次交流的事务边界

1. 检查主体清醒，记录当前 lifecycle revision。
2. 对话库事务预占调用：分配递增序号、保存本次用户输入为 pending、扣除次数。拒绝重复 requestId；并发连接也不能超限。
3. 取已完成问答的连续后缀，最多最近 8 对且共 24000 字符，按原顺序作为 user/assistant 历史；再加本次消息与能力边界提示。不会发送 Pi 历史、主体私有快照或未完成请求。
4. 调用独立模型；不重试、不自动换模型。
5. 校验回复大小/结构/usage，再检查主体仍清醒且 revision 未改变；对话库确认它仍是最新预占序号后，原子提交用户/助手完整问答与模型用量。
6. 只有持久提交成功才返回 reply。错误/取消尽力标记 failed，不返回虚假成功，不退次数。原始错误不保存。

正常失败只留下收费台账，不进入上下文。崩溃时 pending 仍收费、仍不进入上下文，重启不自动补发或重试。最新预占序号屏障拒绝另一进程晚到的旧回复，避免把不按序的交流写入历史；暂时不支持同一会话多进程同时正常聊天。

SQLite 主体库与对话库之间不是一个联合事务。生成结束前的 revision 复查能拒绝已观察到的 sleep/wake，但不保证跨进程 sleep 与对话提交的线性化；没有跨进程即时取消或独占服务租约。服务内 FIFO 的 sleep 要等待正在执行的 say 完成。关闭服务会取消在途模型请求并清理资源。

## 成功、取消和去重

- 成功回复已写库；如果随后网络丢失，客户端仍可能没收到。不能把断线理解为“没有保存”。
- requestId 在该对话库永久唯一，用过后不重放、不再次调用上游；这不是结果重放 API，也不提供恰好一次交付。
- 失败标记自身遇到 I/O 错误时可能保留 pending。次数预占不受影响，不自动清理、退款或再次发送。
- 对话库额度是调用次数，不是货币费用/精确 token 预算。完成调用存储上游 usage；失败或断线的上游实际计费可能未知。

## 隐私、容量与备份

对话正文是私人数据；该模式启用后，用户的 say 输入会作为 pending 持久化，成功助手输出也会保存，失败的用户输入不会进入模型历史但仍在台账中保留。所有 token 持有者共享同一个会话，因此只适用于单一可信所有者，不要共用给多人或不可信插件。

文件创建为 0600；父目录必须可信私有。不加密、不防同 UID 恶意进程，不保证路径检查/打开无竞态。没有自动遗忘、删除、事实提炼、向量检索或长期摘要功能；需要这些能力时应另做明确的数据管理接口，不能让模型自己直接执行 SQL。上下文裁剪不等于磁盘删除。

最多 10000 次预占，每次用户和助手文本各最多 16000 字符，因此总库不是无限增长；该上限仍可能占用可观磁盘。备份时先停止写入并关闭相关服务，分别完整复制主体库和对话库，恢复必须保留其主体 ID 绑定与原额度；不能在写入中直接复制单文件声称是一致备份。新建、替换或回滚对话库会改变预算历史，不是防篡改的账户计费系统。

## 尚未具备

对话跨重启可接续不等于真正学习成长。长期知识仓库、事实/推测提炼、记忆编辑与遗忘、情绪演化、自主活动、外部工具权限、Pi 自动启动均仍需后续实现。
