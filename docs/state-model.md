# 状态模型

## 概念

项目已定案六核心；新领域状态与纯规则见[六核心契约](six-core.md)，其中 `cognition` 独立管理世界认识与瞬时工作空间，`self`补入values/concerns。

显式subject-db模式已接入新core统一持久化，见[运行接线](subject-runtime.md)。以下仅描述原--db兼容服务的 **legacy schema v1**，不适用于新模式：

- **self**：身份、性格、自我认识、兴趣、关系与承诺；不是意识或人格的科学证明。
- **affect**：状态中的情感相关信息或表达维度；情感字段不证明主体具有意识，也不能用来向用户施加负罪、依赖或胁迫。
- **memory**：schema-v1 的主体快照可以保存 `memoryIds`，但它们只是标识符；当前没有读写记忆正文的 `MemoryRepository` 实现，不存在由这些 ID 自动恢复的记忆内容。
- **agency**：动机、意图与当前活动。意图不等于授权；权限由运行边界管理，不能通过修改动机获得。当前没有自主运行或自动执行循环。
- **growth**：状态中可保留 growth proposal 数据，不表示模型已具备学习、持续成长或训练能力。

具体字段、联合类型、初始值与校验规则以 `packages/dawn/src/legacy/` 中的实现为准。`createInitialState` 是显式 bootstrap 帮助函数；程序不会自动创建或重置主体。

## 当前状态与持久化语义

SQLite schema v1 可保存一个主体的完整合法 snapshot。显式初始化时要求主体 `revision=0`，允许 bootstrap snapshot 本身带有非空状态字段；后续已实现的持久状态写入仅为生命周期 `wake` / `sleep`。每次实际变更使用 revision CAS，同时写入完整的新 snapshot 和事件；冲突显式失败，无变化的重复设置不增加事件。重开数据库时，应用从 bootstrap 状态回放生命周期事件，并与快照逐字段比对。

因此，代码目前不是“状态不跨进程重启持久化”；在提供相同 SQLite 文件时，已有主体状态能恢复。反过来，只有在显式创建库并使用它时才有此能力；缺失库不会被自动初始化。schema v1 没有通用主体字段编辑/更新命令，不支持自动迁移旧/未来数据库。持久化、安全及容量限制见[持久化说明](persistence.md)。

SQLite 的 `awake` 是主体数据中的 lifecycle 标记，不代表有存活进程或持续服务。关闭 Pi 不隐式执行 `sleep`。

模型生成内容若用于变更主体，只能作为未信任提案。提交前需校验格式、允许变更范围、权限和所基于的状态版本。模型输出本身不能授权修改、形成事实或触发行动。

## 认识论与隐私约束

未来记忆或记录应清楚区分**事实、推测、想象**，保留必要来源/状态，不得把生成的推测悄然升级为事实。私人信息应按目的隔离和最小化，不得因为“memory”这一概念而默认汇集或向不相关上下文暴露。

当前已有独立主体绑定的持久对话记录，但并非通用知识/记忆条目仓库、多人隐私隔离后端或事实来源验证系统。对话 role 保留“用户说过/模型生成”的证据区别，不自动升级为事实。参见[对话记录与预算](dialogue-memory.md)。SQLite 保存主体快照本身不提供加密或防篡改能力。
